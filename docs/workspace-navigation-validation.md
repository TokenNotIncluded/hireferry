# 工作区切页与会话重设计：性能和回归记录

更新：2026-10-21。

本轮验证确认了切页请求的串行等待减少，并覆盖身份失效后立即清空私有界面、连续切页取消旧请求等行为。**下表是 Node 环境执行真实前端源码、使用合成响应和固定网络延迟得到的结果；它不代表生产接口耗时、浏览器绘制时间或用户实际等待时间。新版浏览器视觉验收目前仍未完成。**

## 1. 五轮、每请求 200 ms 的对比结果

每个版本独立运行五轮；每轮依次打开个人资料、平台会话、求职委托。每个 HTTP 请求均增加 200 ms 等待，包括 GET 和 POST。计时从调用真实 `go()` 开始，到真实页面函数产出的 HTML 首次含有相应内容为止。会话必须含有完整消息正文，列表中的消息摘要不算完成。

| 页面 | 旧版内容就绪中位数 | 新版内容就绪中位数 | 旧版最小—最大 | 新版最小—最大 | 本模型中中位数减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 个人资料 | 401.7 ms | 201.0 ms | 401.4–402.2 ms | 200.3–201.5 ms | 50.0% |
| 平台会话 | 803.7 ms | 202.1 ms | 802.8–822.8 ms | 201.6–204.0 ms | 74.9% |
| 求职委托 | 401.7 ms | 201.2 ms | 400.4–402.9 ms | 201.1–201.8 ms | 49.9% |

原始五轮记录、逐请求的开始/结束时间和统计结果见 [workspace-navigation-200ms.json](validation/workspace-navigation-200ms.json)。百分比由内容就绪中位数计算，仅描述这个固定延迟模型。五个样本不能用于推导生产 P95/P99、并发容量或普遍的速度承诺。

### 请求数量与等待顺序

| 页面 | 内容就绪前请求数：旧 → 新 | 本路由总请求数：旧 → 新 | 内容路径变化 |
| --- | ---: | ---: | --- |
| 个人资料 | 2 → 1 | 3 → 1 | 原先先读取 session，再读取 profile；新版复用仍在有效期内的 session，直接读取 profile。 |
| 平台会话 | 4 → 2 | 5 → 2 | 原先依次读取 session、POST 创建/确保平台会话、读取会话索引、读取消息；新版并行读取已有平台会话的消息和索引。 |
| 求职委托 | 3 → 2 | 4 → 2 | 原先先读取 session，再并行读取 mandate/outreach；新版直接并行读取这两个接口。 |

旧版路由总请求数还包含内容挂载后一次 `/api/ai/eligibility` 请求。该请求不计入表中的内容就绪耗时。新版只在浏览器支持相应 WebMCP 能力时异步查询资格；本测试没有提供该浏览器能力，因此不触发查询。聊天的读回执与轮询不包含在两版总请求数中。

此会话场景使用已有的成员平台会话。首次创建平台会话、会话不存在或无权限、直接打开其他会话等分支有单独行为测试，不能直接套用 202.1 ms 的结果。

### 页面壳的提交

两版都在等待页面数据前同步提交页面壳。此次记录中，旧版壳提交中位数分别为个人资料 0.3 ms、会话 0.2 ms、委托 0.2 ms；新版三者均为 0.1 ms。旧版所有样本范围为 0.2–0.6 ms，新版为 0.1–2.3 ms。

这些值是 Node 中调用 HTML 挂载适配器的时间，**不是首帧、首屏、骨架屏实际可见时间或输入响应时间**。页面壳即时提交在旧版已经存在；本轮可量化的主要收益来自减少数据路径上的串行网络往返。页面壳与会话局部占位的视觉质量仍需真实浏览器确认。

## 2. 测量范围与实现

对比基线是 `qa/base-static` 中保存的原始静态文件，内容对应远端主分支 `cebb3a8b6f9d39bb3e21c3dd0352c3b291ed2571`。新版是完成导航和会话修改、并整合上游 `996afaa5` 的主题及 CLI 登录返回逻辑后的工作副本。本记录和附带 JSON 已替换为该次合并后的五轮测量。工具在一次进程内固定源码快照，避免并行编辑混入不同轮次；两版完整 SHA-256 均记录在 JSON 的 `sourceHashes` 中。

运行环境为 Node v24.19.0。测试工具是 [navigation-latency.test.mjs](../tests/navigation-latency.test.mjs)，执行适配器是 [navigation-harness.mjs](../tests/helpers/navigation-harness.mjs)。适配器读取并执行两版真实 `app.js` 和 `service-ui.js`，新版也执行真实 `requests.js` 和 `cli-auth-return.js`，包括普通路由中的 `takeCliReturn` 检查；基线不存在的模块保持缺省。没有在测试里重写这些请求的先后关系。

适配器只提供运行页面路由所需的 DOM 接口，并记录页面函数产出的 HTML。它不是完整浏览器或布局引擎，也不模拟 CSS、字体、图片、布局、绘制、合成、设备性能或带宽。聊天的浏览器事件绑定、读回执和定时轮询被关闭，两版口径一致。真实会话历史也可以在索引之后渐进挂载；本次等延迟场景中消息请求先于索引完成，因此首次完整 HTML 已包含消息。

每轮先完成登录身份和公开配置初始化，再开始切页计时，模拟普通已登录用户在工作区内切页。没有把登录、冷启动、模块下载或首个会话校验计入结果。没有模拟悬停、聚焦或按下预取，因此表中的收益不依赖预取命中。合成成员、会话和消息仅用于测试，不包含真实账户数据。

## 3. 本轮性能修改

请求和 session 逻辑位于 [requests.js](../static/requests.js)，接入位于 [app.js](../static/app.js)，会话加载位于 [service-ui.js](../static/service-ui.js)。

- 已验证的 session 在内存中最多复用 30 秒；同时发起的校验共享在途请求。主动刷新、身份变化、登录/退出、回到可见标签页等路径重新检查或失效处理。业务接口仍由服务端逐次授权。
- 初次配置和 session 请求并行。会话索引和已知会话的消息并行读取；已有平台会话不会每次打开都重复 POST 创建。
- 普通并发 GET 可以共享一次在途读取，完成后不会因此永久保存结果；各消费者得到独立结果副本。自定义身份/归因头、显式 credentials、强制刷新等请求保持隔离。
- 只有本人资料、求职委托、外联列表允许意图预取；最多保留 6 项、3 秒、单次消费。消息、其他人的资料、管理数据、令牌和支付数据不进入预取缓存。写入、权限错误和身份变化使相关结果失效。
- 新导航取消旧导航的页面读取；提交中的写操作和共享初始化不因普通切页被取消。旧导航结果不能覆盖新页面。
- GET 最多等待 12 秒、写操作最多等待 20 秒，超时显示可操作错误。写入超时不自动重试，界面提醒先确认操作结果，避免重复提交。
- 首页动画模块改为首页按需加载。这项变更未纳入上述延迟数字，模块下载和解析收益需要浏览器独立测量。

根节点提供 `data-navigation-state`、`data-navigation-sequence`、`data-navigation-shell-ms` 和 `data-navigation-ready-ms`，用于后续浏览器观察。会话页的根节点 ready 只说明页面/索引挂载就绪；真正的消息内容应另行观察 `#chat-scroll[aria-busy="false"]` 及消息正文。它们均不能被称为生产整体加载时间。

## 4. 身份与连续切页回归

本轮修复了后台会话请求返回 401 后的界面残留：只把 `state.user` 设为空会使聊天的身份校验提前退出，原来的消息 DOM 和输入框可能仍留在页面。现在当前身份收到 401 时立即清空身份、取消私有请求、停止聊天、清理原身份草稿并切换登录页；身份先于聊天销毁清空，避免销毁流程又保存旧草稿。

[navigation-latency.test.mjs](../tests/navigation-latency.test.mjs) 的四项测试覆盖：

1. 已显示私有消息时，后台请求 401 立即移除消息和可发送表单，跳到登录页，并确保停止聊天时身份已为空。
2. 标签页恢复可见时，session 返回未登录结果或 401，都不会保留旧私有内容。
3. 真实路由函数满足上面的请求数量和调度变化；断言以请求行为为主，避免使用易受机器抖动影响的绝对耗时门槛。
4. 资料请求尚未返回时立即切到委托，旧读取被取消，最终页面只含委托内容，旧页面不能再次提交。

[requests.test.mjs](../tests/requests.test.mjs) 的 14 项测试另覆盖 GET 去重和结果副本隔离、预取白名单/有效期/单次消费、写入后缓存失效、自定义凭据隔离、退出时中断请求、读取和写入超时且不自动重试、强制新鲜读取、失败后可恢复、session 有效期/并发校验，以及退出前的迟到 session 不能恢复旧身份。

整合上游主题及 CLI 代码后再次运行 `node --test tests/*.test.mjs`，**12 个 JavaScript 测试文件全部通过**，包括 CLI 授权返回套件；新增导航测试 4 项、请求测试 14 项全部通过。会话套件包含 **78 项通过**，覆盖权限变化、迟到响应、同会话重新挂载后的拒绝回执、草稿/滚动恢复和输入法发送等行为。此结果不替代提交后的 CI，也不表示本轮重新运行了 Rust、生产后端或真实第三方服务验收。

## 5. 复现

在仓库根目录运行已包含的测试，不需要新增 Node 依赖：

```sh
node --test tests/requests.test.mjs tests/navigation-latency.test.mjs
node --test tests/*.test.mjs
```

准备基线静态目录后，运行五轮 200 ms 的对比；以下路径与本次记录一致：

```sh
HIREFERRY_BASELINE_STATIC=../qa/base-static \
HIREFERRY_NAV_LATENCY_MS=200 \
HIREFERRY_NAV_SAMPLES=5 \
HIREFERRY_NAV_REPORT=../qa/navigation-latency.json \
node tests/navigation-latency.test.mjs
```

`HIREFERRY_BASELINE_STATIC` 指向包含基线 `app.js` 等文件的静态目录。未提供该变量时只验证当前实现，默认每请求 20 ms、每版本一轮，不生成旧版对比。`HIREFERRY_NAV_REPORT` 可将完整样本和当前源码哈希写入指定 JSON 路径；输出目录须预先存在。
