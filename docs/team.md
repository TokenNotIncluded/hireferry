# 团队成员与员工邀请

超级管理员在总控台的「团队成员」页面邀请同事，或为 AI 创建独立员工身份。现有超级管理员仍使用 Passkey；员工通过自己的邮箱验证码或 Google 账号登录。无需共享超级管理员账号，也无需给员工登记超级管理员的 Passkey。

## 真人员工

1. 输入员工邮箱，可填写一个便于识别的名称。
2. SMTP 已启用时，可以勾选「通过本站邮件服务器发送邀请」；也可以只创建链接，复制给同事。
3. 同事打开链接，使用受邀邮箱登录，查看权限并明确确认加入。新账号无需先选择求职者或招聘方身份。
4. 接受后进入业务工作台。超级管理员能看到成员和邀请状态，并可停用或重新启用成员。

邀请默认 72 小时有效，只能接受一次，始终绑定受邀邮箱。Google 登录须返回同一邮箱。打开链接不会消费邀请；错误邮箱、普通个人令牌、员工 AI、WebMCP、超级管理员会话都不能代替受邀者接受邀请。登录期间只在当前浏览器标签页暂存本站邀请路径，邮箱及 Google 登录后返回同一邀请；暂存记录最长保留一小时，过期后可以重新打开原始邀请链接。

邀请链接形如 `https://your-site.example/team/invite#hf_invite_…`。秘密位于 fragment，通过请求正文提交，不进入页面请求的路径或查询。服务端仅保存 SHA-256 哈希，不保存可恢复的邀请链接；邀请创建和重发时显示一次。关闭后如需新的可复制链接，请选择「生成新邀请」。新链接会作废旧链接。默认两次生成间隔至少 60 秒。

「等待加入」「已加入」「已撤销」「已过期」分别记录邀请状态。已加入的邀请不能撤销来踢出员工，应停用对应成员。已有有效邀请时，重复创建返回冲突，避免给同一邮箱产生多个可用链接。已接受或主动撤销的邀请不能重发；可以重新创建一次明确的邀请。过期邀请可以重新生成，前提是该邮箱没有较新的有效邀请。

## 员工权限

当前提供一种员工业务角色 `staff`，对真人和 AI 一致：可以使用现有平台业务功能，包括用户资料和账户处理、岗位、匹配、会话、委托、外联进展、订单、收入统计及审计记录。此角色适合受信任的内部招聘运营成员；本版本没有按岗位、候选人或财务信息进一步分组授权。

员工不能邀请其他员工、管理团队、登记或删除超级管理员 Passkey，也不能签发或撤销平台 AI 凭据。官方 CLI 的 `admin` 授权继续要求超级管理员 Passkey，员工的个人 Bearer、普通 CLI 或 HumanGrant 不会自动获得团队业务权限。团队员工 AI 使用下述独立凭据。

员工可以处理普通客户账户，但不能通过客户管理接口封禁或恢复其他员工、已停用员工或仍有有效待接受邀请的账户。此类账户访问变更同样要求超级管理员本人操作，平台 AI 也不能代办，避免绕过团队管理权限。

浏览器中的 `GET /api/session` 返回：

```json
{
  "user": { "id": "…", "email": "…", "role": "unassigned" },
  "admin": true,
  "super_admin": false,
  "staff": { "id": "…", "name": "…", "kind": "human", "role": "staff", "active": true },
  "bootstrap": false,
  "csrf": "…"
}
```

`admin` 表示能够进入业务工作台；`super_admin` 表示 Passkey 超级管理员。服务器中的原始 `sessions.admin` 不会因员工加入而置为 1，所有团队和安全凭据管理接口仍验证原始超级管理员会话。前端隐藏入口之外，后端也会独立拒绝越权。

停用真人员工即时撤回其业务权限，不删除其普通账户和既有业务记录。每次业务操作在持有数据库锁时复核成员、账户和浏览器会话。重新启用是一次新的超级管理员授权，仍有效的个人浏览器会话可再次使用员工权限。封禁普通账户会同时停用对应员工并撤销其待接受邀请；解除账户封禁不会自动恢复员工资格。

## AI 员工

在「添加 AI 员工」中填入名称，即可获得独立身份及只显示一次的 `hf_staff_` 访问凭据，默认 30 天有效：

```text
URL: https://your-site.example/mcp
Transport: Streamable HTTP
Authorization: Bearer <hf_staff_ credential>
Protocol version: 2025-11-25
```

它也可以调用同权限的业务 HTTP API。该凭据不能操作团队、Passkey、其他凭据或接受真人邀请。每次调用同时核验凭据有效期、撤销状态和对应 AI 成员状态。停用 AI 会永久撤销其现有凭据；重新启用后需要另行生成新凭据。更换凭据会立即作废旧凭据。站点不内置 AI 模型或代替 AI 运行任务。

真人员工按成员区分消息已读游标和发送幂等键，同一人的浏览器与 WebMCP 共用状态；AI 按独立凭据区分。对客户仍显示为平台发言，AI 消息保留 AI 标记，服务器审计和消息作者记录保留实际员工身份。

内部工作台会标出员工名称和当前成员自己的消息；这些内部归属字段只返回给有业务管理权限的调用者。客户消息接口不返回员工名称、内部身份键、会话哈希或凭据编号。

## 邮件与限额

邀请复用 `[smtp]` 的 TLS 连接、用户名密码、`from` 和 `reply_to`。邮件包含本站地址、受邀邮箱、权限说明、到期时间及邀请链接。SMTP 未配置时只能生成链接；请求发送邮件会明确失败，不伪装成发送成功。

如果邮件服务器返回失败，邀请仍然存在并可复制，界面返回 `delivery_status: "failed"`。`sent` 只表示 SMTP 服务器接受了邮件，不代表已到达收件箱。网络发送在数据库事务之外进行；发送期间撤销或更新邀请不会被较晚的邮件结果恢复。

```toml
[team]
invitation_ttl_hours = 72
ai_token_ttl_days = 30
max_members = 200
max_pending_invitations = 100
invitations_per_hour = 30
resend_cooldown_seconds = 60
```

`max_members` 是同时启用的成员数量，接受邀请和重新启用时再次检查，避免并发突破。邀请列表和成员列表最多显示 1,000 条，当前有效成员和邀请优先。创建、重发、启用成员和生成 AI 凭据需要最近 10 分钟内的超级管理员 Passkey 认证；撤销和停用仍允许由有效超级管理员会话及时执行。所有浏览器写操作检查来源及 CSRF，团队管理拒绝 Bearer 和 WebMCP 请求。

## HTTP API

| 方法与路径 | 输入与结果 |
| --- | --- |
| `GET /api/admin/team` | 超级管理员读取成员、邀请与可用邮件/团队配置；不返回秘密 |
| `POST /api/admin/team/invitations` | `{email,name?,send_email?}`，返回邀请、一次性显示的 `invitation_url` 和投递状态 |
| `POST /api/admin/team/invitations/{id}/resend` | `{send_email?}`，默认发送邮件；轮换链接和有效期，原链接失效 |
| `DELETE /api/admin/team/invitations/{id}` | 撤销尚未接受的邀请 |
| `POST /api/team/invitations/preview` | `{token}`，公开预览状态、到期时间、掩码邮箱及当前邮箱是否匹配；不接受邀请 |
| `POST /api/team/invitations/accept` | `{token}`，本人浏览器登录、CSRF 和邮箱匹配检查后加入 |
| `PATCH /api/admin/team/members/{id}` | `{active}`，启用或停用成员 |
| `POST /api/admin/team/ai` | `{name}`，创建 AI 成员，返回仅显示一次的 `token` 与有效期 |
| `POST /api/admin/team/members/{id}/token` | 为已启用 AI 更换凭据，所有旧凭据立即失效 |

## 升级与验证

数据库升级至 schema 9，新增成员、邀请、AI 凭据表及封禁撤权触发器，表结构和版本号在一个事务中提交。现有用户、超级管理员 Passkey、CLI、HumanGrant 和个人凭据原样保留。升级前使用原有在线备份命令；旧版本不能读取 schema 9，回退须使用升级前备份。

本轮执行结果与验证边界见 [团队功能验收](team-validation.md)。

`tests/team_invitations.rs` 覆盖真实邮箱验证码登录后加入、邮箱绑定、显式确认、CSRF、重发/撤销/到期、并发容量、SMTP 本地故障、AI 凭据轮换及迁移回滚。`tests/team_access.rs` 覆盖员工业务操作、凭据边界、注销/撤权/封禁、MCP 和消息已读隔离。前端测试覆盖邀请回跳与拒绝跨站回跳、页面权限、确认操作和邮件失败提示。真实生产 SMTP 收件、Google OAuth 与物理 Passkey 仍由部署环境验收。
