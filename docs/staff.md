# 团队员工邀请（Schema 11）

此页面描述 **人类团队经理（manager）** 的有限业务权限。独立的真人业务员工和 AI 员工见[团队成员](team.md)。超级管理员保持原来的 Passkey-only 身份，员工使用自己的 Google/邮箱验证账户。求职者或招聘方的个人角色不会因为加入团队而被改写。

## 邀请与接收

超级管理员登录 `/admin?tab=staff` → 输入员工邮箱 → 选择「团队经理」 → 勾选 SMTP 邮件或取消勾选仅生成链接。默认有效期 7 天，链接仅在创建时返回；数据库只存 SHA-256 摘要。邮件复用现有 `[smtp]` 配置及 STARTTLS/TLS 连接；生产模式 SMTP 不可用时会返回 503，不会假称邮件已发送。发送失败会撤销当前生成的邀请，管理员可重新发起。

邀请链接为 `/staff/invite/<43 位随机令牌>`。接收者必须以邀请中指定的邮箱登录（邮箱验证码或已验证的 Google 登录）；访问链接不能代替账户验证。接受必须同源并携带会话 CSRF，数据库内事务化校验有效期、是否已接受/撤销、邮件匹配及成员上限，成功后邀请单次消耗。重复点击、不同邮箱、过期、撤销都会拒绝。

成员状态在「团队员工」中可立即停用或重新启用；后台请求每次查询成员当前状态，旧浏览器 Session 不会因为个人仍登录而保留团队权限。个人账户仍存在，原有求职/招聘身份、订单、聊天不改动。

## 权限边界

- **超级管理员**：唯一能通过浏览器管理团队邀请、成员启停、通行密钥及平台 AI 令牌。经理不能访问财务、审计、封禁、优惠码或反馈管理；独立的业务员工权限见[团队成员](team.md#员工权限)。
- **经理（仅交互式个人 Cookie）**：可查看候选人/岗位、匹配工作台、平台沟通、寻找委托并创建或推进匹配；不能修改个人资料、封禁、岗位生效状态、收费、团队成员或特权凭据。
- **MCP/CLI/WebMCP**：个人的普通令牌和 WebMCP 不因为员工身份而升级为管理员身份。经理身份本身不提供经理级 AI 令牌。超级管理员可以另行建立[独立 AI 员工](team.md#ai-员工)，其凭据和权限不会从经理身份继承。

验证点：不同邮箱拒绝、一次性消费、超过 TTL 拒绝、撤销拒绝、封禁拒绝、限速、接受后权限、生效中停用等。此阶段的服务端单元测试位于 `src/staff.rs`。

## 接口

| 方法 | URL | 权限与说明 |
| --- | --- | --- |
| GET | `/api/admin/staff` | 超级管理员：成员和邀请历史（不返回令牌） |
| POST | `/api/admin/staff/invitations` | 超级管理员＋Cookie CSRF：`{email,role:"manager",send_email:true/false}`；返回一次性 `invite_url` |
| DELETE | `/api/admin/staff/invitations/{id}` | 超级管理员＋CSRF：撤销待接受邀请 |
| PATCH | `/api/admin/staff/members/{id}` | 超级管理员＋CSRF：`{active:false/true}` |
| GET | `/api/staff/invitations/{token}` | 未登录也可预览有效邀请与受邀邮箱 |
| POST | `/api/staff/invitations/{token}/accept` | 已验证受邀邮箱 Cookie＋CSRF，空 JSON body |

上限：同时待接收邀请 100 条，每小时最多创建 30 条，同邮箱每分钟最多一次，在职经理最多 100 人。每次创建/查看员工列表会清理 30 天前已接受、已撤销或过期的邀请记录；操作审计保留最小必要字段，绝不记录邀请令牌。需要调整规模时应一并改进可配置限制。

部署须先备份数据库，经理表最初在 schema 11 引入，当前整合版本升级后 SQLite `user_version=13`；旧版本程序会拒绝打开新数据库。真实 SMTP 投递和浏览器 Passkey/Google 交互仍须在目标生产环境验收。
