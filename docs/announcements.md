# Platform announcements

管理员可以在总控台的「公告管理」中编辑一条平台公告，分别填写中文和英文标题、Markdown 正文，并选择：

- **发布公告**：让登录用户在工作台看到公告。
- **要求阅读确认**：公告会持续显示，直到用户点击「我已阅读并确认」。确认状态按公告版本保存；管理员改动正文或确认策略后会生成新版本，用户需要重新确认。

正文会在服务端清洗 Markdown，脚本、外部 HTML 和不安全链接不会进入页面。公告默认停用，不会因为升级自动打扰现有用户。

工作台内容和公告分别加载。公告请求较慢或失败时，简历、岗位和消息仍可显示；公告返回后只更新公告区域，不重建正在填写的表单。离开页面或切换账户后，旧请求不能把公告带到新的页面。

浏览器接口：

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| `GET` | `/api/announcement` | 当前登录用户读取启用公告及确认状态 |
| `POST` | `/api/announcement/ack` | 用当前会话和 CSRF 确认指定版本 |
| `GET` | `/api/admin/announcement` | 管理员读取公告设置 |
| `PUT` | `/api/admin/announcement` | 管理员用 `expected_version` 乐观更新公告 |

公告与平台私聊的自动接待文案分开管理。后者仍由 `[chat.auto_reply]` 配置，并明确说明平台 AI 是异步、主动式服务，处于早期阶段，不是 24/7 实时客服。
