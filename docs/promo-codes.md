# 优惠码：申请、激活与招聘广告

招聘方可以先登录、提交优惠申请，再到申请记录查看审批结果及获批优惠码。平台管理员也可以直接创建优惠码。只有获批后生成的码或管理员创建的码可以兑换；提交申请本身不会改变账户权益。

## 规则

每个优惠码有两组独立额度，均按**整个优惠码的总次数**计算，不按账户重复发放。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 免费激活总次数 `free_activation_limit` | 1 | 用于开通招聘账号；设为 0 即不附带免费激活 |
| 广告使用总次数 `publish_limit` | 1 | 用于创建招聘岗位；设为 0 即不提供广告优惠 |
| 广告减免比例 `discount_percent` | 100 | 整数 0–100；100 表示免费发布，50 表示减免一半，0 表示原价 |
| 启用 `enabled` | true | 关闭后不能用于新的激活或广告订单 |
| 到期时间 `expires_at` | 无 | Unix 秒；到期后不能用于新的兑换 |

次数范围均为 0–1,000,000。优惠码可自定义，留空则生成随机码；输入去除首尾空白、统一为大写，允许 6–64 位字母、数字、短横线和下划线。

知道优惠码的已登录用户可以使用它，实际成功使用受剩余次数限制。不要公开只打算给特定招聘方的优惠码。用户只能读取自己的申请及其中的优惠码；管理员可以查看全部申请与优惠码。

免费激活适用于尚未选择角色的用户和未激活招聘方。兑换成功后，角色成为招聘方并完成激活；已激活账户重试不会再扣一次。求职者账户和被封禁账户不能通过此入口切换或获得招聘权益。免费激活次数与广告次数互不扣减。

广告优惠只作用于新岗位的发布费，不改变工资、币种、编辑次数和后续修改费用。金额使用当前币种的整数最小单位，折后应付按四舍五入计算；不会进行汇率换算。100% 减免生成实付为 0、`provider=free`、`status=paid` 的订单，并在同一事务内发布岗位，不要求配置支付网关，也不创建现金收款账本记录。

## 申请与审批

用户提交 `reason` 后，申请状态为 `pending`。每个用户同时只能有一个待审核申请；完全相同的重复请求返回现有申请。申请人可以在自己的申请列表中查看审核状态、审核说明和获批优惠码。

管理员批准时设置免费激活总次数、广告使用总次数、减免比例、到期时间和启停状态。审批与发码在同一个事务中完成；重复批准返回原结果，不能多发一个码。拒绝后不会生成优惠码，申请人仍能查看拒绝说明。已经审批的申请不能改成相反结果；调整已发优惠码应使用优惠码管理入口。

## 次数与付款

免费发布在创建岗位、订单和使用记录的同一事务中消耗一次额度。付费优惠订单会先预占一次广告额度；预占期间该次数不能用于其他订单。经核验的支付回调完成发布后，预占变为已使用。

预占最长 24 小时；下单时优惠码更早到期的，使用该到期时间。预览、发布下单、读取订单、管理列表和支付结算时会处理到期预占，清空旧支付入口并释放次数。此机制不依赖后台计时任务，因此空闲订单的显示状态会在下一次相关操作时更新。

付费优惠订单在 `snapshot_json.promo.reserved_until` 保存实际预占截止时间。订单页显示优惠付款截止，以优惠预占与支付链接两者中更早的时间为准；本地到期后隐藏支付入口。仍处于待付状态的订单保留取消入口，便于立即释放预占次数。

招聘方可以取消自己的待付优惠发布订单，立即释放预占次数。订单取消或过期后收到迟到付款，平台保留收款记录并标记为 `paid_needs_review`，供人工核对，不再发布岗位，也不会重新消耗已释放额度。重复支付回调不会重复发布、重复记账或重复扣次数。

免费激活会取消同一账户的旧待付开通订单。旧开通单随后收到付款时，同样进入人工核对；已有未核清的实际开通款项时，系统会阻止再使用优惠码激活。

管理员修改折扣不会重算已经创建的订单金额。关闭优惠码会阻止新的兑换，已预占且仍有效的订单继续按下单时的条款结算。修改总次数时，不能低于已使用次数与仍在预占的次数之和。岗位删除或退款不会恢复已经消费的优惠次数。永久删除会清除岗位内容和付费修改中的职位描述；原订单保留当时的优惠码、原价和减免比例，便于核对历史权益，不使用优惠码当前的新设置改写历史。

## HTTP 接口

接口沿用网站会话及 CSRF 检查。审批、创建和修改优惠码在服务端检查管理员身份。分页从 1 开始，每页 25 条，列表返回 `items`、`total`、`page`、`limit`。

| 方法和路径 | 用途 |
| --- | --- |
| `POST /api/promo-applications` | 提交 `{ "reason": "…" }` |
| `GET /api/promo-applications?page=1` | 本人的申请；支持 `status` 筛选 |
| `GET /api/admin/promo-applications?status=pending&page=1` | 管理员审核队列 |
| `POST /api/admin/promo-applications/{id}/review` | 批准或拒绝，见下例 |
| `GET /api/admin/promo-codes?page=1` | 管理员优惠码列表及额度 |
| `POST /api/admin/promo-codes` | 直接创建优惠码，字段与审批 `settings` 相同 |
| `PATCH /api/admin/promo-codes/{id}` | 修改标签、总次数、折扣、启停或到期时间；`clear_expiry: true` 清除到期时间 |
| `POST /api/promo-codes/preview` | 校验可用性并计算激活或发布实付 |
| `POST /api/promo-codes/redeem-activation` | 使用 `{ "code": "…", "currency": "CNY" }` 免费激活 |
| `POST /api/role` | 原角色接口新增可选 `promo_code`；`role` 必须为 `employer` |
| `POST /api/jobs` | 原发布接口新增 `promo_code`、`request_key` 和 `expected_amount_cents` |
| `POST /api/orders/{id}/cancel` | 取消自己的待付优惠发布订单 |

批准申请示例：

```json
{
  "decision": "approved",
  "note": "已批准招聘试用。",
  "settings": {
    "label": "新招聘方试用",
    "free_activation_limit": 1,
    "publish_limit": 3,
    "discount_percent": 100,
    "enabled": true
  }
}
```

拒绝使用 `decision: "rejected"` 并填写 `note`，无需 `settings`。

发布费预览示例：

```json
{
  "code": "HF-EXAMPLE-CODE",
  "purpose": "publish",
  "currency": "CNY",
  "salary_cents": 300000
}
```

预览返回 `promo_code`、`original_amount_cents`、`discount_percent`、`amount_cents`、`currency`、`currency_decimals`。预览不预占次数；提交时重新检查可用性。网页会将用户接受的 `amount_cents` 作为 `expected_amount_cents` 提交。如果管理员在此期间修改折扣或费用，导致实付变化，服务端返回 409，保留额度，不创建岗位或付款订单；用户重新查看并确认报价后再提交。激活预览使用 `purpose: "activation"`，无需工资。

发布示例：

```json
{
  "title": "Rust 开发工程师",
  "jd_md": "维护 Rust 服务。",
  "salary_cents": 300000,
  "currency": "CNY",
  "headcount": 1,
  "promo_code": "HF-EXAMPLE-CODE",
  "request_key": "f39040b2-0124-41b4-a831-0f096d996a90",
  "expected_amount_cents": 0
}
```

有剩余应付金额时还需传入支持该币种的 `provider`。有优惠码时，`request_key` 必填，长度为 8–128 位，允许字母、数字、短横线和下划线。网络重试必须保持相同键和相同业务内容；服务端返回原岗位与原订单。即使重试时已修改默认币种、启用币种、发布费或招聘人数上限，已成功请求仍返回原结果，不重算原订单。相同键用于不同内容会被拒绝。创建另一条招聘广告或在旧单取消后重新发布，应使用新的键。

优惠码余额包含 `activation_used`、`activation_remaining`、`publish_used`、`publish_reserved`、`publish_remaining`，方便区分已消费、预占与还能使用的次数。无效、停用、过期或额度不足的码会明确报错，不会自动改成原价下单。

MCP `choose_role` 和 `create_job` 同样接受优惠码字段；`create_job` 使用相同的请求幂等规则。优惠码不扩大既有 AI 或 HumanGrant 权限，未获得 AI 访问资格的招聘方仍须先在网页完成开通及符合要求的岗位发布。

## 验证

优惠码使用数据库版本 9。由版本 8 升级时，申请、优惠码、使用记录表及相关视图、触发器与版本标记在同一事务提交；此迁移步骤失败时保留版本 8，回滚本步骤新建对象。重复执行迁移不会丢失已有账户、订单或优惠码。

`tests/promo_codes.rs` 覆盖申请隔离和重复审批、默认免费激活、关闭激活权益、两组独立额度、免费发布、失败回滚、重复请求、输入/CSRF/管理员权限、跨 SQLite 连接的最后一次额度竞争、付费预占、取消/过期释放、迟到付款、金额快照和 MCP 参数传递。另有升级失败注入、配置变化后的幂等恢复、报价变化拒绝及永久删除后的原优惠记录保留测试。

```sh
cargo test --test promo_codes
```

相关实现：[`src/promos.rs`](../src/promos.rs)、[`src/promos.sql`](../src/promos.sql)、[`src/commerce.rs`](../src/commerce.rs)。测试使用合成账户与本地 SQLite，未发邮件或请求真实支付网关。
